# Rolodex Contacts — agent guide

Flask + PostgreSQL app with per-account sign-in. The vintage desk-rolodex UI (`vintage-rolodex/`) is served at `/` and `/vintage/`. User-facing docs, the full env-var table and the API reference are in README.md.

## Run and verify

```bash
./runner.sh up      # fresh throwaway stack + smoke tests; last line is RESULT: pass|fail ...
./runner.sh smoke   # smoke tests against the running stack (rerun `up` after editing code; it rebuilds)
./runner.sh test    # up + failure-path checks + down; this is what CI runs
./runner.sh down    # remove the stack, its database and images
```

- Exit codes: 0 pass, 1 tests failed, 2 Docker missing/not running, 3 never ready, 4 build failed.
- Each checkout gets its own Compose project (`dxr-<folder>-<hash>`) and a free host port, so parallel worktrees don't collide. The port changes when the app container restarts; read it from the RESULT line or `docker compose -p <project> port app 5000`.
- `up` wipes its stack's database every time. Never point tests at a database with real data: the smoke tests create accounts, and `/save_contacts` replaces all of an account's contacts.
- Without Docker: `DATABASE_URL=postgresql://... python3 app.py` (needs a Postgres; the app creates its tables on start).

## Code map

- `app.py`: every route, the schema (`init_db()`, run at import under `pg_advisory_xact_lock`) and the DB connection (`get_db_conn()`: `DATABASE_URL`, then `POSTGRES_URL`, then `ROLODEX_DB_*`).
- `migrate_to_postgres.py`: `--owner EMAIL` imports a contacts.json; `--claim-orphans --owner EMAIL` adopts contacts with no `user_id`. It imports `get_db_conn` from `app.py`; don't copy connection or schema code into it.
- `tests/api_integration_smoke.py`: stdlib HTTP smoke tests (`BASE_URL`, exit 2 when no server answers). `tests/failure_paths.sh`: failure-path checks run by `./runner.sh test`. `tests/check_env_docs.py`: fails when README misses an env var the code reads.
- `index.html`, `app.js`, `styles.css`, `sw.js`, `manifest.json` at the repo root belong to the old classic UI. No route serves its page; don't build features there (see TODOS.md).

## Conventions and gotchas

- **Session key**: `ROLODEX_SECRET_KEY` if set; otherwise one key generated by `init_db()` and stored in `app_settings`. The production check (`VERCEL` or `ROLODEX_ENV=production` without a key) must stay above `init_db()`; CI checks it.
- **Health**: `/health` always returns 200 (body says `degraded` when the DB is down). Wait on `/ready` (503 until the DB answers).
- **Errors**: API errors are `{"error": ...}`. The vintage UI shows `error` to people, so keep it short and put agent-facing detail in another field (the 401 uses `hint`). Server errors go through `_server_error()`, which logs an id and returns it.
- **Env vars**: add a README table row for every new `os.environ.get(...)`, or `tests/check_env_docs.py` fails CI.
- **Users and contacts**: every contact has a `user_id`; every query filters on the signed-in user. Emails are stored lowercased.
- **Compose**: the `db` service isn't published to the host; the app reaches it as `db:5432`. On Fedora, bind mounts need `:z`.
- **Vintage UI**: it splits the API's single `name` into first/last (last word = surname) and uses the `company`/`title` columns.
- **AI features**: need `FIREWORKS_API_KEY`; without it the AI endpoints return 500.
